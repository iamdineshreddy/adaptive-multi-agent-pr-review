Phase gating rule: **no phase starts until the previous phase's tests pass.** When a
phase cannot be completed as specified, it is split and documented (never silently
cut).

Phase 3 scope note (deliberate deferral): **FR-1.3 (GitHub API client fetching PR
metadata, changed files, diffs, and commits)** is deliberately deferred to Phase 5,
where the ingestion worker needs that data for analysis. The Phase 3 webhook only
consumes what GitHub sends in the event payload; changed-file-driven priority
factors (security, dependency, component) therefore stay at their documented 0.0
baseline until then.

Phase 4 scope note: the **priority zset, scheduler, and orchestrator fan-out are
wired end-to-end** (webhook → `pr_ingestion_queue` → zset → `queue.pop_and_stage`
→ `queue.pop_and_dispatch` → `orchestrator.run_review` on `review_task_queue`).
Nobody pretends agents ran when they did not: unit + live-DB tests cover the
cores, and broker delivery itself is exercised in Phase 16 integration. Without
a broker, dispatch falls back to the Phase 3 log-only provider via
`queue_dispatch_provider=logging` (default is `celery`, which requires a
reachable broker and surfaces enqueue failure as a 500).

Phase 13 scope note (deliberate split): the dashboard depends on read endpoints
that did not yet exist, so it landed in two documented passes. **Part 1**: read-only
dashboard API (`GET /api/v1/reviews`, `GET /api/v1/reviews/{id}`, `GET
/api/v1/dashboard/summary`) backed by new `OrchestratorStore.review_summaries` /
`review_detail` / `status_summary` read models (Memory + Sql), plus the React +
Vite + TS + Tailwind shell (queue-status dashboard, review list, review detail
pages). **Part 2**: additional read endpoints and store read models — `GET
/api/v1/repositories` + `/{id}` (settings), `/{id}/memory` (snapshot, decay
params, learned weights), `/{id}/feedback` (outcome, source, author, commit),
`GET /api/v1/reviews/{id}/findings` (publication-status filter + pagination),
`GET /api/v1/reviews/{id}/iterations`, `GET /api/v1/metrics` (reviews/findings/
feedback status counts, redundancy rate, agent token/cost/latency rollups) — with
frontend pages: Metrics (stat cards + distribution panels with refresh), and
Repositories (expandable rows with memory snapshot + feedback list panels).
Dashboard authentication (admin/operator/viewer roles, API keys) is deliberately
deferred to Phase 15 (docs/SECURITY.md §4: "Implementation lands in Phase 15");
the read endpoints are unauthenticated reads only, consistent with the Phase 15
authz plan.

Phase 14 scope note (deliberate split): Observability is split because the
Langfuse SDK tracing seam must keep the offline provider surface free of
network/SDK coupling. **Part 1** (this pass): structured JSON logging
(`app.monitoring.logsetup` — ISO timestamps, level filtering, redaction of
secret-shaped keys, wired from `create_app`), a Prometheus exposition endpoint
(`GET /api/v1/monitoring/prometheus`) with real counters (webhook deliveries,
recorded feedback) and store-derived gauges pulled from
`OrchestratorStore.metrics_rollup()` on every scrape (reviews/findings/feedback
by status, redundancy rate, agent token/cost/latency) via
`app.monitoring.prometheus`, plus Grafana provisioning
(`infra/grafana/provisioning/dashboards/adaptive-review.json`) and a Prometheus
scrape config (`infra/prometheus/prometheus.yml`); docs in
`docs/OBSERVABILITY.md`; `prometheus-client` already ships in the `monitoring`
extra (the module is a no-op facade and the endpoint reports `unavailable` when
the dependency is absent). **Part 2** (this pass): Langfuse tracing
(`app.monitoring.langfuse`) — strictly gated on the configured
`ADAPTIVE_LANGFUSE_*` keys, so the offline/mock provider surface never touches
the SDK. `build_llm_provider` wraps the production resilient provider in
`TracedLLMProvider` (a `llm_call` span per completion carrying model, prompt/
completion tokens, cost, latency, success/error; the `mock` path is never
wrapped), and `run_agent` opens one `agent_execution` trace per agent run
(tags: agent key + review id) covering both in-process and Celery execution.
`langfuse` installed from the `monitoring` extra; ROADMAP Phase 14 marked done.

- No fabricated metrics/experiments (research integrity).
